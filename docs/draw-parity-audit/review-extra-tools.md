## Findings

1. **P2. Undo during a laser gesture leaves a permanent red trail.** `src/components/DrawCanvas.tsx:228`, `:232`, and `:767`. Draw a rectangle, select Laser with K, hold the mouse and drag a red trail, press Ctrl+Z while still holding, then release. After 1,200 ms the DOM still contains one `draw-laser-trace` without `is-fading`. Undo replaces the scene and clears `gesture.current` without clearing the unfinished trace. Pointer-up then has no gesture to finish or schedule for removal. View-mode cancellation uses the same incomplete cleanup. A lost pointer capture only handles pan. Screenshot `extra-review-browser/laser-undo-stuck.png` captures the actual failure. Finished-trace timeouts at line 770 also have no tracked handles or unmount/cancellation cleanup. Use one laser cancellation lifecycle for scene replacement, view changes, lost capture, Escape, pointer cancellation, and unmount.

2. **P2. Ordinary eyedropper activation keeps the previous fill target.** `src/components/DrawCanvas.tsx:485`, `:551`, and `:633`. On a rectangle, use Shift+G and click to sample fill. Press I and click again. Chromium reports `Fill sampled: transparent` again, rather than sampling stroke as the menu/docs promise. The menu Eyedropper activation also calls `setActiveTool` without resetting `sampleTarget`. With a selection this silently edits fill when the user asks for the ordinary stroke eyedropper. Make each activation establish its paint target, or expose and document a persistent target explicitly.

3. **P2. Labeled Mermaid LR connectors are entirely hidden by their label backgrounds.** `src/utils/drawExtraTools.ts:87` and `:102`, consumed by `src/components/DrawSceneSvg.tsx:318`. Import `flowchart LR\nA[Start] -->|go| B[End]`. The 170-wide nodes are spaced 250 apart, leaving an 80-unit connector. Every edge label is assigned width 100 regardless of text length. The existing renderer adds a 110-unit opaque backdrop, covering both the entire line and its arrowhead and cutting into the node edges. Chromium inspection measured the backdrop width as 110 and the persisted arrow span as 80. The imported result visibly shows two boxes and “go” with no directed connection. This is also visible in the committed `docs/screenshots/draw-extra-tools/06-editable-mermaid.png` for Start to Choose. Additional screenshot `extra-review-browser/mermaid-labeled-edge.png` demonstrates it. Size labels from text and reserve enough edge space for the visible path and arrowhead.

4. **P2. Import Mermaid commits an unfinished connector preview.** `src/components/DrawCanvas.tsx:382` and `:879`. From an empty drawing, select Arrow, click once at (600,400), and move to (750,500) without finishing the multi-click arrow. Open More drawing tools, Import Mermaid, and import `flowchart LR\nA[Start] -->|go| B[End]`. After autosave, the scene contains seven elements: the six imported elements plus the unrelated unbound arrow from the unfinished gesture. The new dialog handlers never cancel the pending connector, and `insertComponent` merges into `draftRef.current` including its preview. The pending gesture remains alive after import as well. This violates the preview/one-completed-gesture ownership rule and differs from normal tool switching, which calls `cancelConnector`. Cancel or deliberately finish the existing gesture before either extra-content dialog starts, and base the import on the resulting committed scene.
